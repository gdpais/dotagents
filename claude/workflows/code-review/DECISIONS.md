# Decisions — code-review workflow

Skill produced: `defect-first-review`. Sources: `codex:review-agent` (OpenAI-shipped Codex system skill in `.system/`, **not user-authored**), `anthropic:engineering:code-review` (read fully), `anthropic:engineering:testing-strategy` and `anthropic:engineering:tech-debt` (skimmed), user skills `codex:rca` and `codex:postmortem` (house style only).

| ID | Decision | Options considered | Chosen | Rationale | Source |
|---|---|---|---|---|---|
| CR-01 | Provenance of the base discipline | Treat review-agent as user IP; treat it as vendor default; ignore it | Vendor default, adopted because the user shipped it in their skill set | review-agent is OpenAI-shipped (`.system/`, `allow_implicit_invocation: false`, generic display name). The user did not write it, so rule 1 (preserve user IP verbatim) does not bind it; it is still the strongest review contract available and matches the user's evidence-led style, so its rules are kept near-verbatim. | codex:review-agent |
| CR-02 | Skill name | `code-review` (collides), `review-agent` (Codex-ism, "agent" misleads in Claude), `pr-review` (too narrow: also commits, uncommitted, pasted diffs), `defect-first-review` | `defect-first-review` | No collision with `engineering:code-review`; names the distinguishing discipline; kebab-case, no vendor words. | new |
| CR-03 | One skill vs split (resolve / review / post) | Three skills; one skill with references | One skill + 4 references + 1 script | Stages are strictly sequential and share one target identity; splitting would force hand-offs of state. Posting and subagent briefs are rare paths, so they live in references (progressive disclosure). | new |
| CR-04 | Invocation policy | Keep Codex `allow_implicit_invocation: false`; implicit triggering | Implicit triggering on change-review requests, with explicit NOT-for list in the description | In Codex the skill was a delegated worker. In Claude it is the user-facing entry point, so it must trigger on "review this PR". The NOT-for list routes audits, test plans, design, and debugging elsewhere. | codex:review-agent (changed) |
| CR-05 | Relationship to `engineering:code-review` | Delegate to it; wrap it; substitute | Substitute: absorb its dimensions as lenses, replace its output and bar | Its dimensions add coverage the review-agent lacks (named OWASP classes, N+1, indexes, leaks). Its reporting (emoji severity table, "Suggestions", style items, "What looks good") conflicts with the user's no-padding evidence style and review-agent's bar. Both skills stay installed; see open question on trigger contention. | anthropic:code-review |
| CR-06 | Coverage vs filter | Anthropic checklist as reporting criteria; review-agent bar only; combine | Anthropic dimensions = coverage lenses; review-agent five-part bar = sole reporting filter | Lenses stop blind spots; the bar stops noise. A lens with no candidates is a normal outcome, stated in coverage. | anthropic:code-review + codex:review-agent |
| CR-07 | Style / maintainability | Anthropic "Style (naming, structure, readability)" and "Maintainability" dimensions; review-agent "no style nits that do not obscure code" | review-agent wins; maintainability kept only when it raises defect risk | Style comments dilute signal and are not defects. Kept narrow maintainability cases (diverged duplication, meaning-inverting names, dead code hiding the live path). | codex:review-agent over anthropic:code-review |
| CR-08 | Severity scale | Anthropic Critical/Suggestion with emoji; P0–P3 | P0–P3 with review-agent definitions, plus calibration examples | P-levels are finer and tie to "fix next" urgency; examples added (new) to make levels consistent across runs, labeled as calibration not rules. No business severity invented (user's postmortem/rca rule). | codex:review-agent + new |
| CR-09 | Output format | Anthropic table report; review-agent findings-first P-format | review-agent P-format, findings first, `No findings.` allowed | Matches user house style (answer first, no filler). Anthropic "What Looks Good" dropped as padding. | codex:review-agent over anthropic:code-review |
| CR-10 | Verdict | Anthropic free-form Approve/Request Changes/Needs Discussion; none | Advisory verdict derived mechanically from priorities (Blocking / Fix before merge / OK to merge) inside the assessment | Keeps Anthropic's useful bottom line while preventing vibe-based verdicts; states that merge decisions stay with humans (user's authorization-boundary style). | anthropic:code-review (adapted) |
| CR-11 | Explicit confidence and evidence per finding | review-agent format only; add evidence line and confidence | Add `Evidence: ... Confidence: confirmed / plausible (<gap>)` | Mirrors the user's rca/postmortem standard of explicit confidence and named gaps. `plausible` is allowed only when the bar holds and exactly one link is uninspectable; speculative items go to residual risks, never findings. | codex:rca style + new |
| CR-12 | Code examples in findings | Anthropic "actionable suggestions with code examples"; review-agent paragraph only | Paragraph; minimal fix snippet only when the fix is not obvious and fits a few lines | Keeps entries short and focused on the defect; snippets can mislead when the fix needs design context. | codex:review-agent + anthropic:code-review (limited) |
| CR-13 | Target resolution | Ad hoc git commands; helper script | Keep review-agent merge-base rule verbatim; add read-only `resolve_review_target.py` with 10 unit tests | The upstream-ahead rule is fiddly and easy to get wrong; a deterministic helper makes it repeatable. Script only runs read-only git commands (tested: no status/ref change). Tests use `unittest` so they run under pytest or plain Python (pytest not installed here; ran `python3 -m unittest`, 10/10 pass). | codex:review-agent + new |
| CR-14 | Missing local base branch | review-agent: try configured upstream, then fail | Configured upstream, then `<remote>/<branch>` (origin first), then fail | Common Claude case: `main` never checked out locally but `origin/main` exists. Extension is strictly a fallback, logged as a change from the original. | codex:review-agent (extended) |
| CR-15 | PR input | Anthropic "pull PR diff via source control"; review-agent had no PR mode | Support PR URL/number via source-control connector or `gh`; read head via `git show <sha>:path`; never check out | Anthropic adds PR intake; review-agent's read-only rule forbids checkout over the user's tree. Fetching the PR ref is allowed (writes only `.git`), with a note to ask when the user has not sanctioned git operations. | anthropic:code-review + codex:review-agent |
| CR-16 | Subagent fan-out | Never delegate (review-agent); always fan out; conditional | Conditional: single pass by default; parallel lens subagents (security / correctness / performance / data-and-migrations) or path partitions for large or sensitive diffs | review-agent's "do not delegate" existed because it was itself the delegate; the intent (one accountable reviewer, no delegation chains) is preserved: only the coordinator fans out, lens subagents may not delegate, coordinator owns the final list. Size thresholds are labeled heuristics. | codex:review-agent (adapted) + new |
| CR-17 | Verification pass | Trust lens output; coordinator re-check; independent verifier | Every candidate verified against call sites/tests; verifier gets claim + location, not the lens's reasoning; P0/P1 always re-verified by coordinator or a fresh verifier | Implements review-agent step 4 at scale. "Agreement from the same source is not independent corroboration" is taken from the user's rca coordination rules. | codex:review-agent + codex:rca |
| CR-18 | Running checks | Read-only means never run anything; run anything | Allowed: existing local hermetic tests / type checker / linter the repo documents; never migrations, deploys, or writes outside a temp dir; otherwise name the check | Running a pinned test is the strongest confirmation; the limit mirrors the user's "prefer read-only diagnostics" rule in rca. Coverage note distinguishes checks run vs recommended (rca: executed vs recommended tests). | codex:rca style + new |
| CR-19 | Structured findings tool | Always text; always tool | Use a host findings-reporting tool (e.g. `ReportFindings`) when present and the active instructions say to; else P-format text | Hosts that render findings natively get typed output; field mapping given (priority prefixed in `summary`, lens as `category`, verdict CONFIRMED/PLAUSIBLE). Described by capability so it degrades gracefully. | new |
| CR-20 | Instructions files | AGENTS.md only (Codex) | `CLAUDE.md` and `AGENTS.md`, root plus directories of changed files, nearer wins; user request overrides | Claude-native equivalent required by brief; knowledge-base "team standards" from Anthropic folded in via these files (connector optional). | codex:review-agent + anthropic:code-review |
| CR-21 | Stated intent check | Ignore; Anthropic "verify the PR addresses stated requirements" | Read PR description / linked issue / commit message; unmet intent is a correctness finding only if it passes the bar | Useful correctness signal from Anthropic; kept inside the bar so it cannot become requirement nitpicking. Ticket-linking of findings dropped (no defect value). | anthropic:code-review (partial) |
| CR-22 | User focus ("focus on security") | Anthropic tips: narrows review; review-agent custom instructions | Focus narrows lens depth, never lowers the bar; incidental P0 still reported | Keeps review-agent's "custom review instructions" input and Anthropic's tip, without letting focus hide a release blocker. | anthropic:code-review + codex:review-agent |
| CR-23 | Posting comments | Never (review-agent); Anthropic silent | Only on explicit request; clear instruction = authorization for that scope, ambiguous = draft first; default event COMMENT; never approve/request changes/push unless named | Follows the user's rca pattern ("honor one-off authorization without repeatedly seeking approval within that scope") and brief's no-posting default. Connector first, `gh` second, paste-ready fallback. | codex:rca style + new |
| CR-24 | Generated / vendored / lock files | Line-review everything (review-agent "whole diff"); skip silently | Check for consistency only, and list them in coverage | Preserves "whole diff" honestly (nothing silently skipped) without wasting effort on machine output. | codex:review-agent (adapted) |
| CR-25 | Pasted diff with no repo | Refuse; review hunks as if verified | Review as given; findings needing unseen callers are at most `plausible`; limit stated | Avoids overclaiming, per the user's evidence standard. | codex:rca style + new |
| CR-26 | `engineering:testing-strategy` | Delegate; ignore; adopt fragment | Adopt its "what to cover" focus areas to judge material test gaps; hand off for full test plans | Gives the "material test gaps" line a consistent yardstick; a missing test is never itself a finding. | anthropic:testing-strategy |
| CR-27 | `engineering:tech-debt` | Fold in; ignore; hand off | Hand off only (pre-existing issues and code-health audits) | Pre-existing problems are out of scope by the bar; tech-debt's scoring model is for backlogs, not change review. | anthropic:tech-debt |
| CR-28 | Hand-offs | None; many | tech-debt, testing-strategy, engineering:debug / `rca`, engineering:architecture | Gives each out-of-scope concern a home instead of turning it into a finding. `rca` referenced by the user's name for it (ported by the RCA workflow). | new |
| CR-29 | Dropped items | — | Dropped: `agents/openai.yaml`, `argument-hint` frontmatter, emoji severity, "What Looks Good", "Suggestions" table, ticket linking, ASCII "standalone vs supercharged" box | openai.yaml is Codex-only (display name / short description folded into description); brief allows only `name` + `description` frontmatter; the rest is padding or conflicts with the bar. | codex:review-agent, anthropic:code-review |
| CR-30 | Worked example | None; real code; illustrative | Illustrative example (P1 security, P2 N+1, P3 leak, plus assessment/coverage) and a `No findings.` example, marked as not real code | Shows format, evidence line, coverage note, and the clean-result shape without fabricating facts about the user's code. | new |
